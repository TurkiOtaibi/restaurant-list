branches/worktrees in these waves:

| 1 | 001, 002, 008 | Independent foundations: safe E2E, canonical errors, locked backend installs. |
| 2 | 003, 004, 005, 009, 012, 014 | Depend only on Wave 1 foundations and affect separate subsystems. |
| 3 | 006, 007, 013, 015 | Policy/abuse/auth/CSP work after their prerequisites. |
| 4 | 010, 016 | List pagination follows access policy; setup follows final settings/install/image work. |
| 5 | 011 | Profile contract reuses the pagination pattern and canonical errors. |
| 6 | 017 | Documentation aligns only after contract-changing plans settle. |
| 7 | 018 | CI optimization uses final lockfiles, test commands, docs gate, and safe E2E startup. |

Do not merge parallel branches without rebasing and rerunning drift checks. Plans
that touch `.github/workflows/ci.yml`, environment examples, or shared docs are
especially likely to conflict even when their behavior is independent.

## Findings considered and rejected

- Reintroduce rating-driven list removal or "tried" state: rejected because
  Approved EDR-009 intentionally makes ratings and lists independent.
- Treat system-wishlist visibility behavior as a bug: rejected because EDR-013
  explicitly defines the system wishlist contract.
- Enable local-disk image storage in production: rejected because EDR-012 keeps
  production image storage dormant until an external backend is configured.
- Treat Next 15 as an unsupported vulnerability: rejected; it is currently in
  Maintenance LTS. Migration remains a time-bound direction option.
- Create a dependency-vulnerability remediation plan: rejected because both
  `pip-audit` and `npm audit --audit-level=moderate` were clean at the audit
  commit. Plan 008 addresses reproducibility instead.
- Create a committed-secret rotation plan: rejected because no high-confidence
  tracked live credential was found. Plans must never record secret values.
- Create an Alembic branch repair plan: rejected because the repository has one
  migration head and PostgreSQL migration validation exists in CI.
- Label anonymous discovery as a simple authorization vulnerability: rejected.
  Current code, UI, and tests intentionally implement it; Plan 006 correctly
  treats the conflict as unresolved approved-policy drift.

## Executor completion protocol

For each plan:

1. Create the plan's named branch or an isolated worktree.
2. Run the drift check and compare current-state excerpts.
3. Execute steps in order and stop on any STOP condition.
4. Run focused tests, then all required subsystem gates.
5. Confirm `git status --short` contains only in-scope files.
6. Update the status row here and include concise verification evidence.
7. Do not push, open a PR, or publish security details unless the operator asks.
