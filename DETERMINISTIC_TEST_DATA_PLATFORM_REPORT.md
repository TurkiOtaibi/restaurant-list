# Deterministic Test Data Platform Report

## Architecture

Implemented a QA-only deterministic test data platform with separate frontend and backend test-support adapters.

Core pieces:

- Shared QA catalog documentation under `qa/test-data/`.
- TypeScript/Playwright generator and optional API seeder under `frontend/tests/e2e/support/`.
- Python/backend test generator under `backend/tests/support/`.
- Focused proof tests for both frontend and backend test environments.

The platform is not imported by production application code and does not modify application behavior, API behavior, runtime configuration, business rules, or database schema.

## Reusable Fixtures

Reusable fixture types:

- Places
- Lists
- Ratings
- Public/private list metadata
- Ownership/shared/favorite metadata
- Malformed response fixtures for QA-only mocks
- Private-field response fixtures for privacy testing

The TypeScript platform can optionally seed supported visible datasets through the existing test API. Synthetic-only recipes such as deleted, hidden, private, and intentional duplicate-name scenarios are guarded and cannot be seeded through APIs that do not support those states.

## Reset Strategy

- Backend tests continue to use the existing isolated test database reset.
- Playwright E2E seeding uses deterministic namespaces and test-only users.
- Every generated fixture has deterministic IDs, deterministic ordering, deterministic names, and deterministic ratings.
- No random values are generated by the platform.

## Cleanup Strategy

- Backend cleanup is handled by the existing test database lifecycle.
- Playwright cleanup can delete seeded lists through public APIs where supported.
- Places are isolated by deterministic namespace because the current product API does not expose a delete-place endpoint.
- Synthetic-only states remain QA metadata/mock data and do not require product cleanup.

## Known Limitations

- Product states without public API support, such as hidden/deleted/private place state, are generated as synthetic QA metadata and guarded from direct API seeding.
- The current product API does not expose place deletion, so E2E cleanup isolates places by namespace instead of deleting them.
- The platform provides deterministic data; it does not validate business behavior by itself.
