## Production Contract

- Login submits `POST /api/v1/auth/login`.
- Successful login response body is `TokenPairResponse` with `user.id`, `user.email`, `user.displayName`, and `accessToken`.
- AUTH-003 does not document the numeric HTTP success status for login; executable success cases assert only documented successful response body and session effects.
- Successful login sets a refresh cookie with HttpOnly, Secure in HTTPS/production, configured SameSite policy, path `/api/v1/auth`, configured max age, and JavaScript unreadability.
- Successful login keeps access token in frontend memory only and not in `localStorage`, `sessionStorage`, URL, logs, or error payloads.
- Login after a preserved safe protected-origin redirect returns to the original destination/action route.
- Direct login without origin navigates to `/places` as the asserted default authenticated app destination.
- Invalid email and missing/empty password validation return `422`.
- Wrong password and unknown email return `401` with the same documented generic invalid-credentials behavior.
- Login rate limit returns `429` with code `RATE_LIMITED` after the configured threshold is exceeded.
- AUTH-003 does not own protected-route denial mechanics, return-origin storage mechanics, open-redirect sanitization internals, refresh rotation, token lifetime, lockout, MFA, password reset, registration, or social auth.
