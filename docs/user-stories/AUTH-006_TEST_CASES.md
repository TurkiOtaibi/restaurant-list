# AUTH-006 Test Cases

Feature: `AUTH-006 - Protect personal MVP data from guests`

## Sources

- `docs/user-stories/AUTH_USER_STORIES.md`

## Documented Contract

- Guests without a valid access token/session are denied from protected personal
  MVP data.
- Place discovery and explicitly public-list collection/detail are readable
  without an account under EDR-014, with neutral guest context, public-safe
  fields, and bounded anonymous rate limits.
- Protected APIs and routes return or show `401` denial where the AUTH-006 user story documents `401`.
- Protected data must not render to guests.
- Auth-unknown protected pages show loading/pending state and never render cached private data to guests.
- Guest redirect to login preserves the original protected destination/action context for post-login return when safe.
- Return origin is cleared after use or when unsafe/external.
- Unsafe external or unsafe-scheme return destinations are ignored and the app uses the default authenticated destination.
- Guest sign-in prompt/link is labeled, keyboard reachable, and focus is managed.
- Denied states remain usable at `320px`, `390px`, and `200%` zoom without horizontal overflow.

## Shared Assertions

| Assertion ID | Required Assertion |
|---|---|
| ASSERT-AUTH-006-401-SAFE | Response status is `401`; response is structured; response does not include protected data canaries, private notes, hidden metadata, debug payloads, stack traces, SQL details, audit fields, internal identifiers, tokens, credentials, or session internals. |
| ASSERT-AUTH-006-PRIVATE-HIDDEN | DOM text, accessibility tree text, client-side error payloads, network error payloads, logs, and URLs contain none of the canaries from FX-AUTH-006-PRIVATE-001. |
| ASSERT-AUTH-006-NO-MUTATION | Before/after protected data counts are unchanged for the targeted resource; no unauthorized create, update, delete, add, or remove operation changes protected data. |
| ASSERT-AUTH-006-RETURN-SAFE | Preserved return context is same-origin, path-based, and contains only the attempted protected destination/action context; it does not include tokens, credentials, session IDs, private canaries, external origins, or unsafe schemes. |
| ASSERT-AUTH-006-PROMPT-A11Y | Sign-in prompt/link has accessible name `Sign in`, is keyboard reachable, receives visible focus when focused, and focus is managed to the prompt or first actionable sign-in control after denial. |
| ASSERT-AUTH-006-RESPONSIVE | At tested viewport/zoom, sign-in prompt and action are visible/reachable, `document.documentElement.scrollWidth <= window.innerWidth`, no global overflow masking is required, and touch target is at least `44x44` CSS pixels where an action is rendered. |
