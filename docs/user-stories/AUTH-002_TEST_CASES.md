## Production Contract

- Registration submits `POST /api/v1/auth/register`.
- Successful registration returns `201 Created`.
- Successful registration response is `TokenPairResponse` with `user.id`, `user.email`, `user.displayName`, and `accessToken`.
- Successful registration starts a session: access token is held in frontend memory, refresh cookie is set by backend, and the UI navigates to `/places`.
- Display name is required, trimmed, minimum 1 character, maximum 80 characters, and public-safe.
- Email must be valid, trimmed, lowercased, normalized, unique case-insensitively, and not duplicated.
- Password is required, minimum 8 characters, maximum 128 characters, maximum 72 UTF-8 bytes, never returned, never logged, and never exposed.
- Validation failures return `422`.
- Duplicate email is documented as conflict behavior, but the exact numeric HTTP status and exact code are not specified in AUTH-002.
- Rate-limit response handling is covered only as an AUTH-002 recovery input. Rate-limit enforcement, threshold counting, Redis, lockout, MFA, password reset, social auth, and login behavior are not AUTH-002 executable ownership.
